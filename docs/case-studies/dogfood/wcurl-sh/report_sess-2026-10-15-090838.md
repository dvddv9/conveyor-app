# wcurl — Спецификация: Анализ и Рекомендации

[ECHO] Man page для `wcurl` — тонкая обёртка над curl с «sane defaults»: параллельные загрузки, follow redirects, auto-filename, no-clobber, retries, https по умолчанию, отключение globbing. Версионно-зависимое поведение (curl ≥ 7.66.0 / 7.83.0 / 8.16.0). Прямое предупреждение: «never build it from untrusted input».

[ROUTE] stage0 → stage1 (scanner) → stage2 (analyst) → stage4 (synthesizer) → stage5 (transmitter). task_type=spec → обязательны [MATRIX], [INTERSECTION_RISKS].

[CONCLUSION] Спецификация описывает удобную обёртку, но содержит **2 критических риска** (инъекция через `--curl-options`, необратимая перезапись файлов на curl < 7.83.0) и **системное избегание** ключевых для автоматизации аспектов (exit codes, таймауты, параметры retries, поведение при ошибках). Признаков тестов и наблюдаемости не найдено (VERIFY: man page не содержит тестов). Рекомендуется hardening (option A) как interim и config-file-only (option B) как target.

[RISK_NODES]
- **RN-1** (критично): молчаливая деградация на старом curl — нет проверки версии.
- **RN-6** (критично): не документированы exit codes, поведение при ошибках curl, частичных загрузках.
- **RN-8** (критично): retries включены, но параметры (count, backoff, условия) не раскрыты.
- **RN-10** (критично): гонка записи в общий output path; защита только через `--no-clobber` (≥ 7.83.0).
- **RN-2** (важно): «sane defaults» могут конфликтовать с пользовательскими `--curl-options`.
- **RN-4** (важно): тезис «simple wrapper» смещён — фактически сложная логика нормализации.
- **RN-5** (важно): примеры с кавычками противоречат тексту о whitespace-split.
- **RN-7** (важно): дефолт 5 соединений/host — узкое место для массовых загрузок.
- **RN-9** (важно): нумерация файлов при multi-URL + `--output` зависит от curl ≥ 7.83.0.
- **RN-11** (важно): обновление/понижение curl меняет семантику без изменения интерфейса — скрытый breaking change.
- **RN-3** (опционально): конкуренция с прямым curl/trurl.

[PLAN_B]
- SEC-1: allowlist curl-флагов + запрет построения `--curl-options` из недоверенного ввода; curl config file с контролем содержимого.
- SEC-2: санитизация декодированного имени — запрет `..`, `/`, абсолютных путей; ограничение базовой директории.
- SEC-3: явная политика TLS — не отключать проверку сертификатов, предупреждать при downgrade https→http.
- SEC-4: опциональный audit/verbose режим с записью URL и результата.
- SEC-S1: секреты через curl config file 0600 или env/stdin вместо argv.
- SEC-S2: маскирование чувствительных значений в `--dry-run`.
- CONC-1: требовать curl ≥ 7.83.0 при multi-URL + `--output`; иначе явная ошибка.
- CONC-2: опциональный lock-файл или проверка существования перед записью.
- RN-1: проверка версии curl при старте с явным предупреждением о деградации.
- RN-6: документировать коды возврата и поведение при ошибках curl.
- RN-8: документировать параметры retries (число, backoff, условия).
- RN-10: file locking + требование `--no-clobber` для параллельных загрузок.
- BC-1: консолидированная таблица совместимости версий curl.
- BC-2: документировать значимость порядка опций в `--curl-options`.

[THREAT_MODEL]
Компоненты: wcurl CLI (argv parser) → URL normalization → curl invocation builder → curl binary → filesystem / network+TLS.
Trust boundaries: пользователь/скрипт → wcurl argv (недоверенный); wcurl → curl argv (передача управления); curl → сеть/TLS; curl → filesystem.
Threats (STRIDE): **T** — инъекция curl-флагов через `--curl-options` (критично); **D** — перезапись файлов при параллельной записи на curl < 7.83.0 (критично); **T** — path traversal через percent-decode (важно); **I** — утечка секретов в argv/ps/history (важно); **E** — повышение привилегий при запуске от root (важно); **S** — подмена URL через недоверенный ввод (важно); **D** — DoS на целевой сервер при `--parallel-max-host 0` (опционально); **R** — отсутствие audit log (опционально).
Итого: 8 угроз — 2 критических, 4 важных, 2 опциональных.

[SILENCE_LAYERS]
- **Input silence:** нет цифр нагрузки (число URL, размер файлов, частота запусков, число параллельных процессов) → невозможно оценить достаточность дефолта 5 соединений.
- **Assumption silence:** предполагается поддержка всех версионно-зависимых флагов и доверенность ввода в `--curl-options`; деградация молчаливая.
- **Consequence silence:** перезапись файлов без `--no-clobber` необратима; утечка секрета в history/ps необратима.

[INTERSECTION_RISKS]
1. **input_silence × assumption_silence:** нет данных о нагрузке × предположение о поддержке `--parallel-max-host` → на старом curl дефолт 5 не применяется, при массовых загрузках — скрытая перегрузка или неограниченный параллелизм.
2. **assumption_silence × consequence_silence:** предположение о доверенном вводе × необратимая перезапись → недоверенный `--curl-options` с `--output` на системный путь + отсутствие `--no-clobber` = необратимая потеря данных.
3. **input_silence × consequence_silence:** нет цифр нагрузки × необратимая утечка секретов → при массовой автоматизации секреты в argv многократно попадают в ps/history, масштаб утечки не ограничен.

[ASSEMBLY]
Иерархия: **core** — CLI parser, URL normalization, curl invocation builder; **service** — curl binary (version-gated), post-processing (percent-decode, timestamp); **infra** — filesystem, shell/calling process, network+TLS.
Критический путь: `argv → normalize → build curl argv → exec curl → write file`.
Циклов в графе зависимостей не обнаружено.

[REFACTORING]
Варианты:
- **A: Harden wrapper** — version check, allowlist `--curl-options`, sanitize filenames, gate multi-URL+`--output` на curl ≥ 7.83.0, mask secrets в dry-run. Закрывает SEC-1, SEC-2, CONC-1. Backward-compatible.
- **B: Config-file-only** — deprecate argv pass-through, требовать curl config file (0600). Устраняет SEC-1 и SEC-S1 в корне. Breaking change.
- **C: Status quo + docs** — только документация. Не закрывает критичные риски.

[PARALLELS]
- `wget` — аналогичная обёртка с более богатой обработкой ошибок и exit codes.
- `trurl` — URL-манипулятор из экосистемы curl; конкурирует при сложных сценариях.
- Прямой `curl` — рекомендован самой документацией при нестандартных кейсах.
