# wcurl CI Workflow — Compliance Review (D3)

[ECHO] GitHub Actions workflow `test.yml` для wcurl: 4 job'а (lint / debian / fedora / macos), ~180 строк, trigger push+PR на main, concurrency cancel-in-progress, permissions: {} глобально. Материал — CI config, task_type=compliance.

[ROUTE] stage4 → stage3 → stage5. Sequential. research_first=false, parallel_stages=false, subst_count=0.

[CONCLUSION] Workflow структурно зрелый (pinned actions by SHA, REUSE, zizmor --pedantic, concurrency gate), но содержит 3 критических дефекта, подрывающих доверие к зелёному CI: (1) `git clone --revision` — нестандартный флаг, fedora job рискует молча пропустить тесты; (2) hardcoded linuxbrew path в lint job — сломается при дрейфе образа runner; (3) `permissions: {}` при использовании `secrets.GITHUB_TOKEN` — противоречие модели безопасности. Необратимости нет (CI перезапускаем), но накопительный ущерб доверию к пайплайну реален. force_emergency: false — hotfix на 1–2 дня.

[RISK_NODES]
- RN-1 (критично): linuxbrew path hardcoded — lint job упадёт при изменении образа runner.
- RN-5 (критично): permissions: {} vs GITHUB_TOKEN — либо токен недоступен, либо scope неявно расширен.
- RN-8 (критично): git clone --revision — нестандартный флаг, fedora job рискует упасть.
- RN-2 (важно): debian:stable / fedora:latest — плавающие теги, недетерминированный CI.
- RN-4 (важно): lint не блокирует merge отдельно от тестов — размытый сигнал качества.
- RN-6 (важно): zizmor: ignore[unpinned-images] без компенсирующего digest pinning.
- RN-10 (важно): concurrency key pull_request.number || github.sha — push+PR дают разные ключи, cancel не срабатывает.
- RN-11 (важно): плавающие теги могут привнести ломающие изменения без изменения workflow.
- RN-3 (важно, повышен из опционально по CoVe): три источника shunit2 (apt / git clone / brew) — расхождение версий.
- RN-7 (опционально): нет кэша pip/brew/apt.
- RN-9 (опционально): 4 job'а без matrix — дублирование масштабируется.

- RN-3: унифицировать источник shunit2 — один способ с фиксацией версии.

- RN-10: единый concurrency key (github.ref) для всех событий.

[THREAT_MODEL]
Компоненты: GitHub runner (ubuntu-latest, macos-latest), container images (debian:stable, fedora:latest), внешний репо (github.com/kward/shunit2), package sources (brew/apt/dnf/pip), GITHUB_TOKEN.
Trust boundaries: runner ↔ images; workflow ↔ внешние git-репо; workflow ↔ package registries; workflow ↔ GITHUB_TOKEN scope.
Threats (STRIDE):
- T (Tampering) — подмена плавающего тега образа → внедрение кода в CI. Критично. Mitigation: pin по digest.
- S/T (Spoofing/Tampering) — подмена shunit2 репо/коммита. Критично. Mitigation: verify-commit / sha256 архива.
- E (Elevation) — неявное расширение scope токена при permissions: {}. Важно. Mitigation: явный contents: read.
- T (Tampering) — компрометация пакета в registry. Важно. Mitigation: pin версии, lockfile.
- I (Info Disclosure) — утечка GH_TOKEN в логи. Опционально. Mitigation: GitHub маскирует secrets.
- D (DoS) — отсутствие timeout → зависший job. Важно. Mitigation: timeout-minutes.
Итого: 6 threats (2 критично, 3 важно, 1 опционально).

[SILENCE_LAYERS]
- input_silence: нет данных о нагрузке CI (частота push/PR, минуты, бюджет) → невозможно оценить стоимость и необходимость concurrency-оптимизаций.
- assumption_silence: предполагается предустановленный linuxbrew и поддержка `git clone --revision` — оба не проверены и не задокументированы.
- consequence_silence: недетерминированный CI может пропустить регрессию или ложно упасть; ложное доверие к зелёному CI → релиз с багом. Необратимость низкая, но накопительный ущерб доверию.

[INTERSECTION_RISKS]
- input_silence × assumption_silence: нет метрик × предположение о brew → систематические падения lint job могут остаться незамеченными.
- security × concurrency: непpinned образы × cancel-in-progress → отмена в середине установки из непроверенного образа (теоретически для self-hosted).
- assumption_silence × consequence_silence: `git clone --revision` × необратимость доверия → fedora job молча пропускает тесты, зелёный CI без покрытия.

[ASSEMBLY]
Core: trigger (on.push/PR) → concurrency gate → 4 parallel jobs.
Service: lint (REUSE+zizmor+shellcheck+checkbashisms+shfmt+codespell+typos), debian (shunit2 via apt), fedora (shunit2 via git clone), macos (shunit2 via brew).
Infra: GitHub-hosted runners, container images, package sources, внешний репо shunit2, GITHUB_TOKEN.
Critical path: push/PR → concurrency → fedora (git clone --revision) → shunit2 → tests.sh.

[REFACTORING]
Option A — Minimal hardening (1–2 дня): точечно закрыть критические дефекты без реструктуризации. Минимальный diff, быстрый merge, низкий риск регрессии. Дублирование остаётся.
Option B — Matrix refactor + hardening (3–5 дней): единый matrix job (os × distro × shunit2_source), reusable checkout, actions/cache, pin images, явные permissions, timeout, единый concurrency key. Устраняет дублирование, масштабируемо.
Option C — Matrix + SBOM + attestation (5–8 дней): Option B + syft/cyclonedx, actions/attest-build-provenance, digest pinning + dependabot, verify-commit, Brewfile с версиями. Аудируемость, соответствие supply-chain best practices 2026. Overhead времени CI.

[PARALLELS]
- wcurl CI ↔ типовой OSS shell-проект: pinned actions, REUSE, zizmor — современный baseline.
- Три источника shunit2 ↔ классический anti-pattern "multiple sources of truth" для одной зависимости.
- Плавающие теги образов ↔ известный supply-chain anti-pattern (SLSA / NIST SSDF рекомендуют digest pinning).
- permissions: {} vs GITHUB_TOKEN ↔ типичная ошибка минимальных привилегий в GitHub Actions.
