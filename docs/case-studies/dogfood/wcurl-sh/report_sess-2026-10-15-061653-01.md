# wcurl — Анализ README (D3)

[ECHO] Материал — README/manpage утилиты `wcurl` (обёртка над curl, ~180 строк). Уровень D3, task_type=other. Анализ основан на документации; исходный код и содержимое тестов не предоставлены.

[ROUTE] stage4 → stage3 (research_first=false, stage3 не запускался). Синтез опирается на stage1 (scanner) и stage2 (analyst).

[CONCLUSION] `wcurl` — тонкая CLI-обёртка над curl с version-aware defaults. Документация полна по install/usage, но обходит ключевые для автоматизации темы: exit codes, поведение при частичном сбое мультизагрузки, таймауты, идемпотентность. Обнаружены критичный риск инъекции аргументов через `--curl-options` (SEC-1) и важный риск path traversal через percent-decode filename (SEC-2, VERIFY: поведение curl при санитизации пути не проверено). Признаков проверки версии curl при старте не найдено (VERIFY: исходный код не предоставлен).

[RISK_NODES]
- RN-1 (важно): нет проверки версии curl — defaults молча деградируют.
- RN-2 (важно): «sane defaults» конфликтуют с resume-сценарием (`--no-clobber` vs `--clobber`).
- RN-5 (важно): внутреннее противоречие дефолта и resume; пример с кавычками противоречит заявлению «quotes not interpreted».
- RN-6 (важно): не описаны exit codes, поведение без curl, при частичном сбое, при ошибке percent-decode.
- RN-8 (критично): семантика частичного сбоя мультизагрузки не определена — ложные успехи в CI.
- RN-10 (важно): гонка при параллельной загрузке URL с одинаковым итоговым именем.
- RN-11 (важно, VERIFY): обновление curl молча меняет семантику wcurl.

[PLAN_B]
- RN-1: проверка версии curl при старте + предупреждение/ошибка при несовместимой версии.
- RN-2: переформулировать «sane defaults»; вынести resume в отдельный рецепт.
- RN-5: согласовать дефолт и resume — либо разрешить `--continue-at -` без `--clobber`, либо явно предупредить в help.
- RN-6: добавить раздел «Exit codes» и «Error handling» в manpage.
- RN-8: определить семантику частичного сбоя (best-effort vs fail-fast) и итоговый exit code.
- RN-10: рекомендовать уникальные `--output` при параллельной загрузке; предупреждать о гонке.
- RN-11: зафиксировать минимальную поддерживаемую версию curl и тестировать матрицу версий.
- SEC-1: валидация/allowlist флагов `--curl-options`; документировать как недоверенный ввод.
- SEC-2: санитизация percent-decoded filename (запрет `/`, `..`, абсолютных путей).
- SECRET-1: рекомендовать `--config <FILE>` с правами 600 вместо inline-секретов.

[SILENCE_LAYERS]
- Input silence: нет цифр нагрузки (число URL, размеры, параллелизм в реальных сценариях).
- Assumption silence: предполагается доверенный curl в PATH и доверенный `CURL_OPTIONS`.
- Consequence silence: перезапись файла и утечка секретов — необратимы.

[INTERSECTION_RISKS]
- input_silence × assumption_silence: в автоматизации с пользовательским вводом инъекция argv не будет замечена до инцидента.
- assumption_silence × consequence_silence: на curl < 7.83.0 `--no-clobber` отсутствует → молчаливая перезапись → потеря данных.
- input_silence × consequence_silence: при массовой автоматизации секреты в argv попадают в логи без возможности отзыва.

[ASSEMBLY]
- Core: CLI-парсер → URL-трансформер → Curl-argv builder → exec curl.
- Service: testsuite (shunit2), lint (shellcheck, checkbashisms), manpage.
- Infra: curl binary в PATH, FS, сеть, distro-репозитории.
- Критический путь: CLI-парсер → Curl-argv builder → exec curl → FS write.

[REFACTORING]
- Option A (Hardening in-place, 2-3 дня, риск низкий): проверка версии curl, санитизация filename, явный exit code при частичном сбое, маскирование секретов в dry-run, раздел Exit codes в manpage.
- Option B (Strict-mode + allowlist CURL_OPTIONS, 4-6 дней, риск средний): всё из A + deny-by-default для опасных флагов; breaking change.
- Option C (Split wcurl / wcurl-raw, 5-8 дней, риск средний): safe-by-default + passthrough-вариант; не ломает существующих пользователей.

[PARALLELS]
- wget: аналогичная CLI-обёртка, но с собственным HTTP-стеком (не зависит от версии curl).
- aria2: многопоточная загрузка, собственный стек, более сложный конфиг.
- Прямой curl: полный контроль, но требует знания флагов.
- Позиционирование wcurl: «curl для простых случаев» (RN-3).
