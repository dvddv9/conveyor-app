[SILENCE_LAYERS]
- **input_silence**: нет цифр нагрузки (число URL, размер файлов, частота запусков).
- **assumption_silence**: предполагается достаточно новый curl; версии не проверяются явно.
- **consequence_silence**: возможна необратимая перезапись файлов и инъекция флагов; кто — пользователь/автоматизация на недоверенных URL/`--curl-options`.

[INTERSECTION_RISKS]
- **input_silence × consequence_silence**: отсутствие цифр нагрузки × необратимая перезапись → массовая параллельная загрузка без no-clobber (старый curl) = необратимая потеря данных без предупреждения.
- **assumption_silence × security**: допущение о новой версии curl × path traversal в filename → на старых curl нет no-clobber и нет санитизации — усиление риска произвольной записи.
- **security × concurrency**: инъекция через `--curl-options` × параллельные загрузки → подменённый `--output` направляет несколько потоков в один путь — гонка и перезапись.

[ASSEMBLY]
Ядро: argv parser → URL normalization (percent-encode whitespace, scheme default https, globbing off) → filename derivation (percent-decode, `index.html` fallback) → curl argv assembly (version-gated defaults). Сервис: curl invocation / `--dry-run` print, exit-status propagation, output path resolution. Инфра: curl binary (гейты 7.66 / 7.83 / 8.16), filesystem, shell/argv, `~/.curlrc` + env (`http_proxy`, токены). Критический путь: argv parse → URL normalize → filename derive → curl argv assemble → curl exec → filesystem write. Циклов нет.

[REFACTORING]
Три опции:
- **A: Harden-in-place** (2–3 дня) — версия-чек, санитизация filename, маскирование секретов в dry-run, документирование exit-кода, флаг `--resume`. Минимальная поверхность, сохраняет тезис «thin wrapper».
- **B: Contract-first** (4–6 дней) — A + контракт exit-кода, агрегация per-URL статуса, структурированный лог, дефолты `--max-filesize`/`--max-time`. Automation-friendly, но большая поведенческая поверхность.
- **C: Delegate complexity** (1–2 дня) — минимальные изменения: только санитизация + version warning; явно делегировать resume/auth/proxy/globbing curl/trurl. Наименьший объём, но RN-5/RN-6/RN-8 остаются открытыми.

[PARALLELS]
- `trurl` (см. See-also) — параллельный инструмент для URL-манипуляций; та же философия тонкой обёртки.
- `curl --config` — штатный механизм передачи сложных аргументов; wcurl документирует его как workaround для whitespace.
- Паттерн «convention-over-configuration» (sane defaults) — как в `wget`, `aria2c`; но там контракт exit-кода определён явно.
