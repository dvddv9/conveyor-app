[THREAT_MODEL]
Компоненты: curl WS client, embedding app, remote WS server, TLS layer, curl_multi event loop.
Границы доверия: app↔curl (in-process), curl↔server (network), curl↔TLS provider.
- **STRIDE-T (критично):** некорректная валидация WS-фреймов (masking/opcode/length) → memory corruption. Митигация: fuzzing парсера, строгая валидация по RFC 6455.
- **STRIDE-S (критично):** MITM при слабой TLS-верификации. Митигация: обязательная верификация по умолчанию, документировать CURLOPT_SSL_VERIFYPEER.
- **STRIDE-D (важно):** DoS через бесконечные фреймы / ping-flood / huge fragmentation. Митигация: лимиты размера фрейма, rate-limit ping/pong, таймауты.
- **STRIDE-I (важно):** утечка WS payload в debug-логах (CURLOPT_VERBOSE). Митигация: маскировать payload.
- **STRIDE-R (важно):** нет audit log WS-событий. Митигация: документировать debug-callback и CURLINFO.
- **STRIDE-E (важно):** privilege escalation через callback из чужого потока. Митигация: явная thread-safety модель.

Итого: 6 угроз — 2 критично, 4 важно.
